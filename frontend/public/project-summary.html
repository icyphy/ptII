工作原理

系统通过 ReAct (Reasoning + Acting) 模式将 LLM 的推理能力与 Ptolemy II 仿真引擎的执行能力结合。 用户输入自然语言目标，Agent 自动规划并通过 Tool API 操作模型。

系统架构

⚛️

前端 — React + TypeScript

Vite + Tailwind CSS + React Flow (画布) + Recharts (波形) + Zustand (状态管理)。 三栏布局：左侧组件库/示例，中间画布+结果面板，右侧 Agent Chat/Inspector。

☕

后端 — Java REST Server

HttpServer + org.json，暴露 RESTful API。 SessionManager 管理多会话，每个 Session 封装一个完整的 Ptolemy II 模型实例。

🤖

Agent — ReAct Loop

AgentLoop 驱动 LLM (DeepSeek/OpenAI) 的 Function Calling。 进度感知循环：有成功就继续，连续失败自动停止。最高安全上限 80 轮。

🏛️

Ptolemy II 内核 — 零改动

MoMLParser 解析模型片段，MoMLChangeRequest 增量修改，Manager 驱动仿真。 所有修改走 ChangeRequest 路径，自动支持 Undo/Redo。

Tool API — 人机共用入口

无论是 LLM 自动建模还是用户手动操作，都通过同一套 Tool API 操作模型。 这是"原生 Agent 化"的核心设计：保证一致性、可追溯、可撤销。

Tool功能示例参数
add_entity添加 Actor 到画布className, name, x, y
connect连接两个端口from: "Sine.output", to: "Scale.input"
set_parameter设置参数值entity, parameter, value
delete删除 Actor 或关系name
disconnect断开连接from, to
validate检查模型合法性（无参数）
run执行仿真（无参数）
list_library搜索可用组件query, limit

关键设计决策

🔗 统一 Tool API

Agent 和用户走同一条 MoMLChangeRequest 路径 — 保证模型一致性，自动支持 Undo/Redo。

🛡️ 不让 LLM 直接写 MoML

强制走 Tool Calling 而非让 LLM 生成完整 XML — 单步成功率从 <30% 提升到 80%+。

📈 进度感知循环

不设死板步数上限。有进步就继续，连续失败才停止 — 复杂模型不再被人为截断。

🧩 Ptolemy 零改动

所有新增代码在 org/ptolemy/agent/ 包内，Ptolemy 内核作为 JAR 嵌入，可独立升级。

🔄 实时同步

每次 ChangeRequest 完成后前端自动刷新 Graph + Signals — 画布和数据始终是最新状态。

💾 Vergil 兼容

模型保存为标准 MoML XML，可直接用 Ptolemy II Vergil GUI 打开查看和运行。
